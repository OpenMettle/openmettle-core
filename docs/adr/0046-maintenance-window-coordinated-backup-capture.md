# ADR 0046: Maintenance-window coordinated backup capture

- **Status:** Accepted
- **Date:** 26 November 2026
- **Ticket:** V1-30 ([openmettle-core#27](https://github.com/OpenMettle/openmettle-core/issues/27), [openmettle-core#26](https://github.com/OpenMettle/openmettle-core/issues/26))
- **Related ADRs:** [ADR 0028](0028-telemetry-contract-and-metrics.md), [ADR 0031](0031-filesystem-artifact-storage-and-streaming-multipart.md), [ADR 0040](0040-transactional-quotas-and-reservation-reconciliation.md), [ADR 0041](0041-retention-purge-and-deletion-journal.md), [ADR 0044](0044-own-inference-proxy-and-binding-free-dispatch.md), [ADR 0045](0045-credential-vault-and-external-connection-lifecycle.md)

## Triggering problem

`ARCHITECTURE-v1.md` requires a nightly (`24h` RPO) coordinated, encrypted backup of every authoritative OpenMettle store to an off-workstation failure domain, paired with Grandfather-Father-Son (GFS) retention (`7 daily, 4 weekly, 3 monthly`) and immediate alerting on backup failures or overdue schedules (`openmettle.backup.runs`).

Taking uncoordinated copies of PostgreSQL, the POSIX artifact volume, and optional Graphiti/Neo4j state risks:

- skewed artifact ledger rows versus on-disk payloads, causing post-restore `storage rebind` / `quota verify` drift or accidental worker unlinks;
- unsettled quota holds, in-flight worker turns, active external-connection credential refreshes, or unreported gateway dispatches;
- missing deletion-journal watermarks required by [ADR 0041](0041-retention-purge-and-deletion-journal.md) to stop purged artifact revisions and revoked external connections from resurrecting after a restore;
- coupling v1 backup consistency to storage-specific CSI, LVM, or ZFS snapshot drivers rather than generic POSIX PVCs.

V1 therefore adopts a short, explicitly coordinated maintenance window that pauses new write admission, drains in-flight work, captures a single verified encrypted recovery set across all authoritative stores, and reports run outcomes and RPO compliance through OTLP/Prometheus telemetry.

## Decision

Implement PostgreSQL-coordinated maintenance-window backup capture in `openmettle-core` (`migration 0045`, `src/backup`, `openmettle-admin backup`), promote the reserved telemetry signal `openmettle.backup.runs`, and codify explicit consistency, custody, encryption, retention, and recovery invariants.

### 1. Coordinated maintenance gate and durable run ledger (Migration 45)

Migration `0045_maintenance_backup_coordination.sql` (pure 7-bit ASCII, `SQL_ASCII` and `WIN1252` safe, acquiring `ACCESS EXCLUSIVE` on `openmettle.authorization_audit` via a bounded `NOWAIT` retry loop) adds two `openmettle_owner`-owned tables with zero direct table or column privileges for runtime roles (`openmettle_api`, `openmettle_worker`, `openmettle_issuance`, `openmettle_gateway`, or `PUBLIC`):

- **`openmettle.backup_maintenance_gate`** (singleton `id boolean PRIMARY KEY DEFAULT true CHECK (id)`):
  - Tracks stable `installation_id` (UUID generated once per installation), `maintenance_active`, `backup_run_id`, `entered_at`, `entered_by_operator_id`, `reason`, `quiesced_at`, `rpo_target_seconds` (default `86400`, bounded `[3600, 604800]`), `rpo_tracking_armed_at`, `last_overdue_observed_at`, durable cumulative `overdue_count`, and `updated_at`.
  - `backup_maintenance_gate_state_check` enforces that `backup_run_id`, `entered_at`, `entered_by_operator_id`, `reason`, and `quiesced_at` are all `NULL` when `NOT maintenance_active`, and that `entered_at`, `entered_by_operator_id`, and validated `reason` (`capacity_valid_name(reason, 512)`) are populated whenever `maintenance_active = true`.
- **`openmettle.backup_runs`**:
  - Durable append-only lifecycle ledger (`draining -> capturing -> publishing -> succeeded | failed | incomplete`) with unique `request_key`, `operator_id`, `started_at`, `lease_until`, `quiesced_at`, `completed_at`, `destination_domain`, `encryption_key_id`, `bundle_digest`, `manifest_digest`, deletion-journal watermarks (`journal_origin_us`, `journal_seq`, `journal_chain_digest`, optional `lifecycle_origin_us`, `lifecycle_baseline_digest`, `connection_origin_us`), redacted ASCII `failure_code`, immutable `opened_maintenance` ownership flag, and `manifest_summary`.
  - A `BEFORE UPDATE OR DELETE` trigger (`enforce_backup_runs_transitions`) forbids row deletion, freezes staged publication metadata while `state = 'publishing'`, and strictly forbids any update to a terminal row (`succeeded`, `failed`, or `incomplete`).
- **Audit trail:** `openmettle.authorization_audit` widens its action and target-kind constraints to record `backup.maintenance_entered`, `backup.capture_started`, `backup.capture_succeeded`, `backup.capture_failed`, `backup.maintenance_released`, and `backup.rpo_armed` (`actor_kind = 'operator'`, target kinds `backup_maintenance` and `backup_run`). `backup_start_capture` reserves `(operator_id, request_key)` immediately via `backup.capture_started` (and all maintenance/RPO functions reject keys already present in `backup_runs`), while terminal `backup.capture_succeeded` and `backup.capture_failed` audit rows use distinct run-scoped keys (`backup.capture_succeeded:<run_id>` / `backup.capture_failed:<run_id>`) recording `capture_request_key` in `details`.

### 2. Deadlock-free admission closing, SQLSTATE contracts, and in-flight drain

- **Canonical lock order:** Runtime write transactions acquire a lightweight `FOR SHARE` lock on `backup_maintenance_gate` via `SECURITY DEFINER` function `openmettle.backup_maintenance_lock_open()` (granted only to `openmettle_api` and `openmettle_worker`), which raises `SQLSTATE OMM01` while `maintenance_active = true`. Session issuance (`openmettle_issuance`) and native handoff writes are fenced identically via `SECURITY DEFINER` trigger `openmettle.enforce_issuance_maintenance_gate()` on `local_sessions` (`BEFORE INSERT`) and `native_handoffs` (`BEFORE INSERT OR UPDATE`), keeping `openmettle_issuance` and `openmettle_gateway` privileges completely unchanged. Owner maintenance/capture functions and `openmettle.backup_observe_telemetry()` lock strictly `backup_maintenance_gate -> backup_runs -> authorization_audit` (insert-only) and never lock runtime data tables, making `backup_maintenance_gate` a pure lock sink that cannot deadlock with runtime writers.
- **Read-only status check:** `openmettle.backup_maintenance_is_active()` (`SECURITY DEFINER`) is granted only to `openmettle_api` and `openmettle_worker`.
- **Runtime behavior while `maintenance_active = true`:**
  - **`openmettle-api`:** refuses mutating `/v1` operations (projects, conversations, branches, run admission/cancellation, approval decisions, artifact uploads and revision retain/restore transitions, retention policy writes, quota mutations, external connection mutations, and browser/native session issuance including `/auth/native/token` before handoff consumption) with HTTP `503 unavailable`.
  - **Open during drain:** `/healthz`, `/readyz`, `/v1` `GET` reads (including `GET /v1/admin/retention/status` and `POST .../effective-configuration` preview), settlement of already-reserved artifact uploads, already-claimed worker run settlement (including spill reservations where `run.is_some()`), already-claimed artifact purges (`finish_inflight_purges`), and gateway usage settlement remain open so acknowledged in-flight work finishes cleanly.
  - **`openmettle-worker`:** `claim_next` and `reclaim_next` return `Ok(None)`, new `retained -> purging` claims are paused while `finish_inflight_purges` drains already-claimed `purging` revisions to `purged`, already-claimed turns finish and settle, and the maintenance loop continues sweeping `backup_observe_telemetry()`.
- **Bounded drain & fail-closed recovery:**
  - `openmettle-admin backup capture` maintains a continuous background lease-renewal heartbeat (`backup_renew_lease`) while polling six in-flight drain counters (`runs`, `storage_reservations`, `artifact_revisions` purges, unsettled `gateway_requests` with `state = 'reserved' OR (state = 'handed_off' AND NOT settled_final)`, active `external_connections` refreshes, and unconfirmed `capacity_grants`).
  - Once drained, capture opens a single `REPEATABLE READ` transaction, exports its snapshot via `pg_export_snapshot()` together with its `transaction_timestamp()` (recorded via `backup_mark_quiesced(run_id, snapshot_ts, lease_seconds)` as the authoritative recovery-point `quiesced_at`), locks `restore_reconciliation_gate` and `storage_volume_control` `FOR SHARE`, re-verifies quiesce and accounting/filesystem drift inside that snapshot, marks the run `capturing`, and captures `pg_dump --snapshot=<id>`, gateway entitlements, deletion journal, settled artifact inventory, vault key IDs, and schema version from that same snapshot.
  - Any drain timeout (`failure_code = 'drain_timeout'`), drift error, lease loss, or dump/I/O failure removes `.staging.<run_id>`, marks `backup_runs.state = 'failed'`, and keeps `maintenance_active = true` for explicit operator recovery.
  - `--release-on-success` calls `openmettle.backup_release_capture_maintenance(...)`, releasing the gate only if this capture run itself opened maintenance (`opened_maintenance = true`) and still owns the window; inherited maintenance windows remain active until explicit `openmettle-admin backup release-maintenance`.
  - Releasing maintenance while an unexpired capture lease or an unpublished `publishing` run is held fails with `SQLSTATE OMB02` unless the operator explicitly passes `--abort-active-run` after confirming the capture process has exited (transitioning an active lease to `incomplete` or a `publishing` run to `incomplete` with `failure_code = 'publication_aborted'`).

### 3. Per-component consistency and custody boundaries

| Component | Bundle entry | Consistency & custody rule |
| --- | --- | --- |
| PostgreSQL 18 | `pg.dump.enc` | `pg_dump --format=custom --schema=openmettle --no-owner --snapshot=<id>` captured against the exported quiesced `REPEATABLE READ` snapshot; preserves schema objects and bounded role ACLs without touching `public` (post-restore `openmettle-migrate` reapplies owner global `ALTER DEFAULT PRIVILEGES`). Both `sqlx` (`PgConnectOptions::new_without_pgpass()`) and `pg_dump` resolve identical explicit `host`/`port`/`user`/`dbname`/`sslmode` values from `OPENMETTLE_ADMIN_DATABASE_URL` against a closed parameter allow-list (rejecting `hostaddr`, unpaired `sslcert`/`sslkey`, Unix sockets with TLS-required modes, and ambient `PG*` overrides). For `verify-ca` and `verify-full`, a preflight TLS handshake (`verify_pg_tls_preflight`) validates the server strictly against ONLY `sslrootcert` (zero system/WebPKI fallback roots) before opening any SQLx pool or closing admission, and `CliPgDumpRunner` isolates `libpq` from `$HOME/.postgresql/*`, `~/.pgpass`, and `~/.pg_service.conf` via an ephemeral `0700` directory (`0600` `PGPASSFILE` unlinked on drop). |
| `openmettle-gateway` | `gateway-entitlements.json.enc` | Stateless under [ADR 0044](0044-own-inference-proxy-and-binding-free-dispatch.md); PostgreSQL is authoritative (`gateway_consistency_mode = "postgresql_authoritative_adr_0044"`). Captures quota defaults, overrides, budgets, family policies, and authoritative final usage summaries (joining `gateway_settlements` to `gateway_usage_reports` on `(request_id, revision)` where `final`) inside the single exported snapshot. |
| POSIX artifact PVC | `artifacts.bin.enc` | Deterministic `OMART01` stream over generic POSIX files (no CSI/LVM/ZFS dependency). Verifies `.openmettle-volume-id`, `O_NOFOLLOW`, `nlink == 1`, `payload_ino`, empty `staging/`, exact `size_bytes`, and live SHA-256 against PostgreSQL metadata while holding the snapshot `FOR SHARE` barriers. |
| Deletion journal | `deletion-journal.bin.enc` | Exported via `restore::export_conn()` inside the single exported snapshot and watermark-pinned in both `manifest.json.enc` and `backup_runs` so post-restore `restore lock` + `restore replay` runs directly from the unpacked set. |
| Graphiti / Neo4j | `neo4j.dump.enc` (optional) | Explicitly declared via `--graphiti-mode not-provisioned` (default) or `--graphiti-mode offline-dump --neo4j-dump <PATH>`. Opened once via `O_NOFOLLOW` at preflight and checked for non-empty stability across encryption. Never silently omitted or inferred. |
| Chroma vectors | `chroma.archive.enc` (optional) | Explicitly declared via `--chroma-mode not-provisioned` (default), `--chroma-mode archive --chroma-archive <PATH>` (opened once via `O_NOFOLLOW` and encrypted as `chroma.archive.enc`), or `--chroma-mode qualified-rebuild --chroma-qualification-ref <REF>`. Chroma is never assumed rebuildable without an explicit qualification reference. |
| Non-secret config | `config.json.enc` | Explicitly declared `--config-file NAME=PATH` files plus non-secret `vault_required_key_ids` inventory. Opened via `O_NOFOLLOW`, refusing reserved `vault-key-inventory.json`, keyring/vault paths/inodes (failing closed on unreadable vault configs), PEM private keys, and JSON secret fields. |
| External vault keys | Excluded (off-host) | External-connection vault master keys ([ADR 0045](0045-credential-vault-and-external-connection-lifecycle.md)) and backup encryption keys stay in separate off-host custody outside every backup. |
| Rebuildable indexes | Excluded (declared) | Manifest always lists `["postgresql_secondary_indexes", "derived_search_and_fulltext_indexes"]`, and includes `"chroma_vector_embeddings"` **only** when `chroma.mode = "qualified_rebuild"`. |

### 4. Streaming AEAD encryption, destination isolation, CLI, and GFS retention

- **Dedicated backup keyring (`BACKUP_KEYS_CONFIG`):** Version-1 JSON manifest (`0400`/`0600`, owner-only) referencing 32-byte key files (`0400`/`0600`). Loader validates non-zero keys, rejects duplicate keys (`subtle::ConstantTimeEq`), wraps material in zeroizing `SharedSecret`, and refuses any path, `(dev, ino)`, or key-byte overlap with `OPENMETTLE_*_VAULT_KEYS_CONFIG` (failing closed if a configured vault keyring or key file is unreadable).
- **Chunked AEAD wire format (`OMBKUP01`):** 64 KiB chunks encrypted via HKDF-SHA256 per-file keys and AES-256-GCM (`ring`, zero new Cargo dependencies, `unsafe_code = "forbid"`), binding canonical AAD `(backup_run_id, artifact_role, key_id, chunk_seq, is_final)` with strict EOF and trailing-byte rejection.
- **Two-phase staged publication (`capturing -> publishing -> succeeded`) & destination guard:** Stages `.enc` components and `manifest.json.enc` inside `.staging.<backup_run_id>` (`0700` dir, `0600` files), `fsync`s files, staging, and `dest_root`, commits `openmettle.backup_stage_publication(...)` (`capturing -> publishing`, leaving `completed_at = NULL` so neither `succeeded` telemetry nor the RPO clock advances prematurely; resolving any `tx.commit()` error via a `FOR SHARE` locking read on `backup_runs` and preserving staging on `CommitOutcomeUnknown`), atomically publishes `backup-meta.json` via a CSPRNG-unique exclusive `0600` temp file in `dest_root` -> `sync_all()` -> rename into `.staging.<backup_run_id>/backup-meta.json` -> `fsync_dir(staging)` -> rename to `backup-<YYYYMMDDTHHMMSSZ>-<backup_run_id>` -> verify + `fsync` `backup-meta.json`, `final_dir`, and `dest_root`, and finally commits `openmettle.backup_confirm_publication(...)` (`publishing -> succeeded`). Retrying with the exact same `--request-key` checks `backup_runs` before loading `--config-file` or `--neo4j-dump` and idempotently completes, verifies, and `fsync`s publication from `.staging.<backup_run_id>` or `final_dir`. `openmettle-admin` permanently enforces `allow_local_test_paths = false`, refusing `/tmp`, `/var/tmp`, `$TMPDIR`, git workspaces, artifact-root overlaps, and keyring overlaps, and enforces `--require-separate-device` against `--artifact-root` (or `/` when DB-only) and backup key custody directories/inodes (failing closed on un-canonicalizable key paths).
- **Owner CLI (`openmettle-admin backup`):**
  - `status`: reports `installation_id`, gate state, RPO target/armed timestamp, last succeeded run, and latest run status.
  - `enter-maintenance` / `release-maintenance [--abort-active-run]` / `arm-rpo [--rpo-seconds N]`: idempotent, operator-audited maintenance and RPO controls.
  - `capture`: runs the full coordinated workflow (optional `--release-on-success`, default verified GFS pruning scoped to `(installation_id, destination_domain)` unless `--no-prune`).
  - `verify` / `unpack` / `prune [--backup-keys-config PATH] [--dry-run]`: offline AEAD + SHA-256 + `bundle_digest` verification, `0700` unpack ready for `pg_restore` -> `openmettle-migrate` -> `restore lock` -> `storage rebind` -> `restore replay`, and verified `7 daily, 4 weekly, 3 monthly` GFS retention grouped per `(installation_id, destination_domain)` (authenticating `manifest.json.enc` and checking component `.enc` ciphertext digests before any set can enter retention buckets or supersede older sets, leaving unverified sets untouched and reported in `skipped_unverified`).

### 5. Telemetry promotion (`openmettle.backup.runs`) and RPO monitoring

- Promotes `openmettle.backup.runs` (`openmettle_backup_runs_total`, `outcome ∈ {succeeded, failed, incomplete, overdue}`) from `reserved_signals` into active `metrics` in `contracts/telemetry/v1.json` (`17` metrics, `480` data-point streams, `1,208` Prometheus series per process; [ADR 0028](0028-telemetry-contract-and-metrics.md)).
- `openmettle-worker` calls `SECURITY DEFINER` `openmettle.backup_observe_telemetry()` (`FOR UPDATE SKIP LOCKED`) every maintenance tick to:
  1. expire abandoned active backup leases to `incomplete` while keeping `maintenance_active = true`;
  2. evaluate RPO overdue state whenever `rpo_tracking_armed_at IS NOT NULL` and `now() - coalesce(max_succeeded_quiesced_at, rpo_tracking_armed_at) > rpo_target_seconds` (anchoring RPO age to the captured recovery point `quiesced_at` rather than confirmation time, throttled to at most once per hour via `last_overdue_observed_at`), persisting durable `overdue_count = overdue_count + 1`;
  3. return durable cumulative totals `(succeeded, failed, incomplete, overdue)` (counting only `state = 'succeeded'`, never `publishing`) synchronized monotonically (`fetch_max`) into the worker's `openmettle.backup.runs` counters at startup before the first maintenance sleep and on every tick; `encode_otlp` withholds `openmettle.backup.runs` until the first DB seed so restarted workers never export a premature `0 -> N` jump for pre-existing historical failures or overdue counts.
- Fresh dev/test databases start unarmed (`rpo_tracking_armed_at IS NULL`) and arm automatically on the first capture or via `openmettle-admin backup arm-rpo`, avoiding spurious `overdue` alerts before scheduling is enabled.
- `contracts/telemetry/alerts-v1.yaml` adds `OpenMettleBackupFailedOrOverdue` (`for: 0m`, `severity: critical`, `component: backup`, `service: openmettle-worker`), verified by `contracts/telemetry/alerts-v1-test.yaml` under `promtool test rules`.

## Alternatives considered

- **Online PITR + CSI volume snapshots:** Deferred to post-v1 uninterrupted backups (`itemId=307064202`) because it requires storage-class-specific snapshot controllers and continuous WAL archive orchestration.
- **Adding external encryption/archive crates (`age`, `tar`, `flate2`):** Rejected to keep zero new Cargo dependencies and keep the streaming AEAD and archive formats minimal, auditable, and `unsafe_code = "forbid"`.
- **Auto-releasing maintenance on capture failure:** Rejected because drain timeouts, accounting drift, or destination I/O failures require explicit operator inspection before reopening mutation admission.

## Consequences

- Nightly coordinated backups incur a brief mutation-admission pause while reads, health probes, and in-flight run/upload/gateway settlements stay open.
- Because `pg.dump.enc` is captured inside maintenance, restoring `pg.dump` boots with `maintenance_active = true` as extra defense-in-depth until the operator completes `openmettle-migrate`, `restore lock`, `storage rebind`, `restore replay`, pre-worker checks, and `backup release-maintenance --abort-active-run`.
- Uninterrupted zero-maintenance backups (continuous WAL/PITR and online snapshot coordination) remain explicitly deferred (`itemId=307064202`).
